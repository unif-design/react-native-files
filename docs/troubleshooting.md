# 排障

先按 `status` 和 `error.reason` 判断结果，再结合宿主原生日志排查。下表保留库的错误原文；不要通过这些中文消息匹配业务分支。

| 结果或错误原文                              | 检查方向                                                                           |
| ------------------------------------------- | ---------------------------------------------------------------------------------- |
| `当前平台不支持本地文件操作。`              | 确认当前是原生应用，并检查 bundler 是否选择了 Web 入口                             |
| `本地文件路径无效。`                        | 使用正确编码的绝对 `file://` URI，拒绝裸路径、未转义的 `?`／`#` 或畸形编码         |
| `源文件与目标文件不能相同。`                | 核对正规化后的路径，不能仅比较原始 URI 文本                                        |
| `目标文件已存在，不能覆盖。`                | 为复制或下载分配新的独占目标，并检查进行中的同目标调用                             |
| `请明确使用 UTF-8 或 base64 读取本地文件。` | 传入 `encoding: 'utf8'` 或 `'base64'`                                              |
| `写入内容必须是字符串。`                    | 在内容所属层完成序列化，写入只接收字符串                                           |
| `目录不能作为单个文件删除。`                | 核对目标；只有已授权整个目录范围时才使用目录清理                                   |
| `本地文件大小不可用。`                      | 检查原生元数据和 RNFS 补丁，不将缺失大小补成零                                     |
| `本地目录清理未完成。`                      | 分别处理 `partial`／`failed` 和 `failures`，检查目录权限、快照目标与并发写入       |
| `无法确认本地目录直接子项的归属。`          | 检查目录项真实路径、Unicode 名称、链接与别名，不通过改名或字符串大小写转换绕过确认 |
| `下载地址、目标或限制参数无效。`            | 使用 HTTP(S) 地址、合法独占文件目标、非负安全整数大小和正数超时                    |
| `文件下载响应未成功。`                      | 查看 `http` 错误的真实 `statusCode`；认证恢复由所属接入处理                        |
| `下载文件超过大小限制。`                    | 这是 `size_limit`，不是用户取消；核对当前调用显式传入的 `maxBytes`                 |
| `本地资源公开根目录无效。`                  | 创建访问对象时的同步配置错误；检查根 URI                                           |
| `静态服务 SDK 无法安全表示此公开根目录。`   | 根路径不能包含双引号或以反斜杠结尾                                                 |
| `文件不在本地资源公开根目录内。`            | 核对实际根和文件路径，不能只按目录名子串映射                                       |
| `本地资源 HTTP 服务正由其他对象持有。`      | 复用应用持有的共享对象；不要抢占其他实例                                           |
| `本地资源 HTTP 服务不可用。`                | 查看 SDK 启动和平台接线；下一次显式获取可重试                                      |
| `本地资源访问已关闭。`                      | 当前对象已开始关闭，不再交付 URL                                                   |
| `本地资源 HTTP 服务关闭失败。`              | 保留失败并核对 SDK 状态，不能宣称端口已经释放                                      |

## 原生模块缺失或补丁失败

确认宿主安装了全部 peer，实际版本与[补丁对应版本](host-setup.md)一致。本包不提供或自动应用补丁；检查宿主统一维护的补丁源和显式应用结果，从实际消费者的解析位置核对 SDK 副本，再重新安装 Pods、编译应用。不要只重启 JavaScript 来验证原生修改。

同一个依赖存在多份安装副本或不同补丁时，核对实际消费和原生构建选中的版本与修正内容。保留宿主统一流程，处理冲突后在干净安装中验证；不以顶层清单或补丁工具退出成功代替实际副本检查，也不静默跳过失败。

## 下载进度、取消和残留

未知总长度时没有 `totalBytes`；没有最终成功结果前，不使用 100% 进度或目标路径推断完成。超时支持见[下载 API](api/download.md)，特别是 iOS 独立连接超时和 Android 重定向分支。

取消只请求停止本次任务，函数仍负责接收原生终态和清理结果。清理诊断失败可能留下本次目标，宿主按所有权处理；不要删除请求列表中的所有路径，也不要将成功交付的文件交给迟到取消清理。

## 链接成功但资源未加载

`getUrl()` 不检查文件存在或发起 HTTP 探测。核对文件仍可读、服务尚未关闭，以及实际 WebView 对回环 HTTP 的支持。不要把 URL 构造成功作为原生服务或 H5 加载验收。

`cause` 可能包含原始 SDK 信息，只保留在内部诊断；向用户或外部协议反馈时使用已确定的状态和必要说明。
